# Security and privacy operations

Contact delivery fails closed with HTTP 503 until Resend and Turnstile credentials and a verified sender are configured. The recipient defaults to clasintl676@gmail.com. Never put secrets in public runtime configuration or commit .env. Use a verified domain sender, not the Gmail address, as CONTACT_FROM; replies can still go to Gmail.

Private runtime configuration keys: resendApiKey, turnstileSecretKey, turnstileHostname (recommended exact production hostname), contactFrom, contactTo. Nuxt environment variables: NUXT_RESEND_API_KEY, NUXT_TURNSTILE_SECRET_KEY, NUXT_TURNSTILE_HOSTNAME, NUXT_CONTACT_FROM, NUXT_CONTACT_TO. Public keys: turnstileSiteKey, ga4Id, clarityId (NUXT_PUBLIC_TURNSTILE_SITE_KEY, NUXT_PUBLIC_GA4_ID, NUXT_PUBLIC_CLARITY_ID).

The form API validates fields with Zod, rejects the honeypot, verifies Turnstile server-side, escapes HTML, limits attempts to five per 15 minutes per directly connected IP, and reports delivery failures. The in-memory rate limit is per server instance and is not a distributed protection. Configure Cloudflare WAF rate limiting for /api/contact before production, and a shared Redis counter if operating multiple instances. Do not blindly trust user-supplied forwarded IP headers. Restrict body sizes at the platform or security middleware to 16 KB.

Configure HTTPS redirects, HSTS only after HTTPS works on all relevant hosts, CSP, X-Content-Type-Options nosniff, Referrer-Policy strict-origin-when-cross-origin and frame-ancestors 'none'. Allow scripts only from self, Cloudflare Turnstile and consent-enabled analytics providers; permit Maps only in frame-src. Test CSP with the actual Nuxt production build before enforcing it. Do not set unsafe-eval in production. Check the browser console after changes.

Analytics scripts load only after explicit acceptance. Decline stores the choice without loading analytics. Withdrawing acceptance reloads the page to remove active scripts; disclose that provider cookies may remain and provide browser deletion instructions. Avoid sending names, phone numbers, emails or messages in analytics. Enable Clarity masking and review its data processing terms and cross-border transfer arrangements before enabling it.

Set a documented contact-enquiry retention period before launch. Limit access to the receiving mailbox and Resend dashboard; periodically delete expired enquiries and delivery logs, and respond to access/deletion requests through the business email. Have the bilingual privacy draft reviewed for the actual Saudi PDPL processing arrangements.

Use two-factor authentication and separate least-privilege accounts for hosting, email, DNS and any future CMS. Enable domain registrar lock. Store encrypted backups of content and brand assets outside the hosting account; test restore quarterly. Run npm audit and review high/critical findings before deployment and during monthly maintenance. Rotate credentials after exposure or staff access changes. Never include customer enquiries in public backups or logs. Renew security.txt expiry annually.

Patched simple-git and its argument parser with compatible source overrides, eliminating the initial critical findings. `npm audit` still reports 22 upstream findings (18 high, 4 moderate) in development/content/style tooling and their dependency chains. Several underlying advisories had no published patched release at verification time (braces, node-forge, older selector parser). Do not downgrade Nuxt to the obsolete version suggested by automatic forced remediation. Re-run the audit before public launch and review exposure of any deployed server artifact. The private static preview does not execute these Node development tools.
